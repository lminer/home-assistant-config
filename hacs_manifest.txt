## Panasonic Blu-ray -- deliberately NOT a custom component

The media room player is a DP-UB820 on stock firmware. It uses the CORE
panasonic_bluray integration (configured in configuration.yaml) for STATUS, and
Broadlink IR for the buttons -- because UHD-series players reject network control
commands without a per-device player key that the core integration does not
implement. Nothing to install.

Noted here because the obvious move, if that hybrid ever grates, is to reach for a
custom component -- and there are two, both with real drawbacks:

  matteoraf/ha-panasonic_ub         # Full keymap (dpad, eject, subtitle, audio, skip,
                                    # scan) over the same network protocol, on stock
                                    # firmware. This is the one to use if the built-in
                                    # gets too thin. Caveats: not in HACS and not even
                                    # installable as a HACS custom repository -- no
                                    # releases, no hacs.json -- so it is a manual copy
                                    # of custom_components/panasonic_ub/ with no update
                                    # notifications. As of 2026-08-05 the repo was one
                                    # day of commits with 2 stars. It exposes a
                                    # panasonic_ub.remote_command service rather than a
                                    # remote entity, so the dashboard panel would call
                                    # that service directly.

  albaintor/panasonic_bluray_remote # Ruled out. Last touched May 2024, and wants the
                                    # player's firmware PATCHED for current models.


## Notes

- Lutron is the CORE lutron_caseta integration, not a HACS install. Earlier
  versions of this file listed rzulian/lutron_lip; it is not in
  custom_components/ and holds no config entry, so it was dropped on 2026-08-05.
  What survived the change is the part that matters for a rebuild: the setup
  still needs the cert/key/pem files at the config root (lutron_caseta-*.pem),
  and those come from the supervisor backup, not this repo. Without them the
  bridge will not pair and the Pico automation in automations.yaml goes dead.

- richo/homeassistant-franklinwh is NOT in the default HACS index -- checked
  against hacs/default, and the upstream "publish on HACS" issue (#12) was
  closed in May 2025 without the repo being listed. Add it via
  HACS > three-dot menu > Custom repositories:
    Repository: https://github.com/richo/homeassistant-franklinwh
    Type:       Integration
  After that it updates through HACS like anything else. Note its hacs.json sets
  content_in_root, so the component files live at the repo root rather than
  under custom_components/ -- HACS handles that, but a manual install would not.

- Installing a plugin via HACS writes it to www/community/ and registers a
  Lovelace resource. This repo tracks .storage/lovelace_resources, so the
  resource list is restored by ./sync.sh push -- but the plugin JS files
  themselves are not tracked and must come from HACS.
